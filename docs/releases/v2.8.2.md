# v2.8.2

A corrective account-management and runtime reliability release. No user configuration migration is required.

This release closes five related reports: manual/incognito OAuth login, uninstall cleanup, selection diagnostics, persisted token invalidation, and window-aware quota deferral. It also carries the runtime ownership, storage-context, and Windows helper hardening needed to make those fixes reliable across long-running and concurrent installs.

Landed as [#658](https://github.com/ndycode/codex-multi-auth/pull/658), closing [#652](https://github.com/ndycode/codex-multi-auth/issues/652), [#653](https://github.com/ndycode/codex-multi-auth/issues/653), [#654](https://github.com/ndycode/codex-multi-auth/issues/654), [#655](https://github.com/ndycode/codex-multi-auth/issues/655), and [#656](https://github.com/ndycode/codex-multi-auth/issues/656).

## OAuth handoffs

### Manual and incognito login now preserves the exact authorization URL

When the browser flow cannot be used — for example, when signing in through an incognito window or another browser — the login command now presents the complete authorization URL. Browser and clipboard fallback paths use that exact URL, and the terminal prompt remains tied to the matching login attempt, so pasting the callback URL from the manual flow no longer fails with a misleading state-mismatch error ([#652](https://github.com/ndycode/codex-multi-auth/issues/652)).

## Uninstall and runtime cleanup

### Package guidance distinguishes the current and legacy names

The installed package is `codex-multi-auth`. The older scoped package name is called out as legacy, so the uninstall instructions no longer send users to a package command that cannot remove the installed package. The cleanup path removes current and legacy caches, configuration entries, launcher metadata, and runtime bind artifacts with the existing retry policy, including transient Windows `EBUSY`/`EPERM` failures ([#653](https://github.com/ndycode/codex-multi-auth/issues/653)).

### Runtime helper ownership is checked before shutdown

The app-bind and runtime-rotation helpers now carry a per-bind identity token and verify the recorded process identity, timestamp, command, and script path before attempting cleanup. Windows app-server helper shims use an independent `codex.exe` copy rather than a hard link to the running Node image, allowing cleanup to proceed without inheriting a file lock. Shutdown remains best-effort when ownership cannot be established, so an unrelated process is not treated as this package's helper.

## Selection diagnostics

### `why-selected` now agrees with runtime routing

`codex-multi-auth why-selected` now awaits live selection and feeds the same availability gates and runtime policy inputs used by the rotation proxy. Paused or drained accounts, policy-blocked accounts, token-invalid accounts, quota/cooldown exclusions, and policy score boosts are represented in the diagnostic instead of producing a winning candidate that the runtime would never serve ([#654](https://github.com/ndycode/codex-multi-auth/issues/654)).

## Token invalidation

### Revoked OAuth accounts are visible and stay out of rotation

When the upstream provider reports a token invalidation, the account now stores a timestamp and the provider error code alongside its existing auth-failure state. The account is marked `token-invalid — re-login needed` in account status, health/check output, forecasts, live probes, and selection diagnostics, and it is excluded from routing instead of repeatedly re-entering the pool after a short cooldown.

A successful token refresh or login clears the marker and returns the account to normal selection. Existing account files are normalized safely on load; malformed invalidation fields are discarded rather than treated as a valid failure state ([#655](https://github.com/ndycode/codex-multi-auth/issues/655)).

## Quota scheduling

### Long quota windows defer until their trusted reset

The preemptive quota scheduler now uses a finite, future reset timestamp from a trusted quota snapshot when a weekly or monthly window is exhausted. This prevents an account known to be unavailable for days from cycling back into routing after the flat two-hour fallback and producing a predictable live 429.

Missing, stale, expired, or invalid reset data continues to use the bounded fallback. Quota identity is stable per account record, so snapshots survive account-index changes, refresh-token updates, and runtime account reloads without confusing distinct accounts that share an email or provider account id ([#656](https://github.com/ndycode/codex-multi-auth/issues/656)).

## Upgrade notes

No migration is required. Install the package and confirm the version:

```bash
npm i -g codex-multi-auth
codex-multi-auth --version
```

The command should report `2.8.2`.

If an account displays `token-invalid — re-login needed`, sign in to that account again:

```bash
codex-multi-auth login
```

The marker clears after a successful refresh or login. For removal, run the package's cleanup command first and then remove the installed package by its current name:

```bash
codex-multi-auth uninstall
npm uninstall -g codex-multi-auth
```

The legacy scoped package name is not the package installed by this release.
